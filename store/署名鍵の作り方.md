# 署名鍵(keystore)の作り方 ― 図形ハンター

Android の AAB には**アップロード鍵**での署名が必要です。鍵はアプリごとに1つ作り、
**一生使い続ける**もの(紛失すると同じ鍵で更新できなくなる)なので、作成とバックアップは慎重に。

環境(確認済み):
- keytool(JDK17): `C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot\bin\keytool.exe`
- **保管場所**(他アプリと同じ流儀。`keys chemigame` / `keys kobungame` に揃える):
  `G:\その他のパソコン\マイ ノートパソコン\Others\snaplace\game\keys kakudomenseki\kakudomenseki-release.keystore`
  ※ フォルダは作成済み(README.txt 入り)。リポジトリの外なのでコミットされません

---

## 1. 鍵を作る(自分の PowerShell で実行)

パスワードを対話で聞かれるので、**この作業だけは自分の手で**実行してください。

```powershell
& "C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot\bin\keytool.exe" `
  -genkeypair -v `
  -keystore "G:\その他のパソコン\マイ ノートパソコン\Others\snaplace\game\keys kakudomenseki\kakudomenseki-release.keystore" `
  -storetype PKCS12 `
  -alias kakudomenseki `
  -keyalg RSA -keysize 2048 -validity 10000 `
  -dname "CN=Seiichiro Kabashima, O=snaplace, L=Tokyo, C=JP"
```

- パスワードは2回聞かれます(確認用)。**強いパスワードを1つ決めて、パスワード管理ツールに保存**。
  他アプリと同じ流儀にするなら、同じフォルダの `pass.txt` にも控えておく。
- PKCS12 形式なので keystore と鍵のパスワードは同一です(「key password」を聞かれたら Enter で同じにする)。
- `-validity 10000` = 約27年。Google の「2033年10月22日以降まで有効」という条件を満たします。
- `-dname` は証明書の名義。上は他アプリと同じ内容にしてあります(変更しても構いません)。

### 控えておく4つの値

| 項目 | 値 |
|---|---|
| keystore のパス | `...\Others\snaplace\game\keys kakudomenseki\kakudomenseki-release.keystore` |
| alias | `kakudomenseki` |
| keystore パスワード | 自分で決めたもの |
| key パスワード | 同上(PKCS12 なので同じ) |

> **バックアップ必須**: この keystore とパスワードを失うと、同じ鍵でアプリを更新できません。
> クラウドストレージ等に暗号化して保管してください。
> (Google Play アプリ署名を使う場合は、万一のときアップロード鍵の再発行を申請できますが、頼らない方が安全です)

## 2. Codemagic では Android を扱わない

このリポジトリの `codemagic.yaml` は **iOS ワークフローだけ**です
(Mac は分単価が高いので、TestFlight に上げたいときだけ手動で回す運用)。
Android の AAB は **手元で作ります**(§3)。つまり **Codemagic に鍵を登録する必要はありません**。

CI でも Android を署名したくなったら、`codemagic.yaml` に Android ワークフローを足したうえで、
keystore を base64 にして環境変数(`KEYSTORE_BASE64` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`)で
渡す形にします。さわる物理の同名ファイルにその手順が残っています。

```powershell
# 参考: base64 に変換してクリップボードへ
[Convert]::ToBase64String([IO.File]::ReadAllBytes("G:\その他のパソコン\マイ ノートパソコン\Others\snaplace\game\keys kakudomenseki\kakudomenseki-release.keystore")) | Set-Clipboard
```

## 3. ローカルで署名つき AAB を作る場合

**これが普段の手順です**(fumi / chemi と同じ運用)。パスワードは
`..\keys kakudomenseki\keystorePASS.txt` からスクリプトが直接読むので、入力は要りません。

```powershell
powershell -ExecutionPolicy Bypass -File "tools\build_aab.ps1"
```

やっていること・注意点は [`tools/README_BUILD.md`](../tools/README_BUILD.md) を参照。

### 署名されたか確認

```powershell
& "C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot\bin\keytool.exe" `
  -printcert -jarfile "G:\その他のパソコン\マイ ノートパソコン\Others\snaplace\game\kakudomenseki\build\android\kakudomenseki.aab"
```

証明書の所有者(CN=Seiichiro Kabashima …)が表示されれば署名済みです。

### アップロード前に AAB の中身を検証する

設定ファイルを見るだけでは不十分で、プリセットの上書きや古いテンプレの混入は成果物にしか出ません。
Play に弾かれる3点(16KBページ・targetSdk・versionCode)を実物で確認します。

```powershell
python store/check_aab.py build/android/kakudomenseki.aab
```

**署名つきリリース版で確認済み**(2026-08-10 / `build/android/kakudomenseki.aab` 57.1 MB):
- 破損なし(全エントリ展開可)
- 16KB ページ: **OK**(arm64 の .so が align=16384)
- targetSdkVersion: **36** / minSdkVersion: 24
- パッケージ名: `jp.snaplace.kakudomenseki` / versionName 1.1
- **リリース鍵で署名済み**(AAB の証明書 SHA256 が keystore と一致)
- 日本語フォント同梱 / ストア用画像・テストは同梱されない(`exclude_filter` で除外済み)

> 注意: 事前に **Android ビルドテンプレートのインストール**(Godot エディタ → プロジェクト → ツール →
> Android ビルドテンプレートをインストール)と、エディタ設定の Android SDK パス設定が必要です。
> `export_presets.cfg` は `gradle_build/use_gradle_build=true` なので、gradle ビルドが走ります。

## 4. やってはいけないこと

- **リポジトリに .jks を入れない**(`.gitignore` で `*.keystore` `*.jks` `*.p12` を除外済み)
- パスワードをコマンド履歴に残さない(`-storepass` をコマンドラインに直接書かない)
- 鍵をアプリごとに使い回さない(1アプリ1鍵。他アプリと同じ鍵にすると事故の影響が広がる)
