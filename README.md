# 図形ハンター

**角度と面積を、数字で撃ち落とせ。中学・高校・大学受験。**

図形の「角度」と「面積」の問題を、中学受験・高校受験・大学受験の 3 コースで解く学習ゲーム。
問題は図形つきで出題され、答えの数値をキーパッドで入力して解く。
値は毎回ランダムに生成されるので、答えの丸暗記はできない。
スマホ縦持ちが基準。([さわる物理](https://github.com/skabashima/sawarubutsuri) と同じ構成の Godot プロジェクト)

## 動かし方

1. Godot 4.7 以降でプロジェクトを開く(`project.godot`)
2. F5 で実行(メインシーン: `scenes/main.tscn`)

CLI から:

```
godot --path "<このフォルダ>"
```

## コース(角度編 20 + 面積編 45 = 全 65 ステージ)

| 編 | 内容 | ステージ例 |
|---|---|---|
| **角度編** | 角度の問題だけを進む | 三角形の角、時計の針、正多角形と対角線、ブーメラン形、折り返し、星形、円周角、弧の比、作図でできる角、三角形の五心、三角方程式、ベクトルのなす角、2 直線のなす角、空間のなす角 |
| **面積編** | 長さ・面積・体積の問題を進む | 三角形の面積、道の面積、長方形の中の点、葉っぱ形、三平方、相似比、立体の体積と表面積、水そうと水位、展開図、立体の切断、図形の移動、角錐と円錐、空間の三平方、多面体とオイラー、ヒポクラテスの月、方べきの定理、チェバとメネラウス、二等分線と中線定理、余弦定理、ヘロン、点と直線の距離、円の方程式、領域と最大最小、空間図形の体積、空間ベクトル、6分の1公式、回転体と曲線 |

大学受験レベルは 数I(三角比)・**数A 図形の性質**(五心・方べき・チェバ/メネラウス・
角の二等分線・中線定理)・**数II 図形と方程式**(2 直線のなす角・点と直線の距離・
円の方程式と軌跡)・**空間図形**(なす角・四面体と外接球)・**数III**(回転体の体積・
媒介変数と極座標の面積・曲線の長さ)まで入っている。

各編の中は **中学受験 → 高校受験 → 大学受験** の順に易しいものから並び
(一覧にレベルの見出しつき)、前のステージをクリアすると次が開く。
中学受験レベルには入試の応用問題(時計の針・ブーメラン形・折り返し・
正多角形の対角線・道の面積・長方形の中の点・底辺の比と面積比)に加えて、
**立体(体積と表面積・水そうと水位)・図形の移動・相似で長さを出す**まで収録。
高校受験レベルは 平行線と線分の比・相似比と体積比・角錐と円錐・空間の三平方・
作図でできる角・多面体とオイラーの定理まで。
ステージの中でも 1 問目 → 3 問目でバリエーションが難しくなる。
無理数が出る問題は「√3 = 1.73 として」のように明記して小数で答えさせる。

問題はプロシージャル生成で、**問題文と答えの組だけ数えても約 30,000 通り**
(`tests/variation_report.tscn` で実測。図の数値の違いまで含めるとさらに多い)。
各ステージは **難度ラダー(tier 0〜9)** を持ち、tier を「解法の種類 × 数値の難しさ」に
割り当てている。通常ステージは tier 0〜2、挑戦モードは 0〜9 を 1 問ずつ登るので、
挑戦 10 問では数字だけでなく**解法そのものが問ごとに変わる**。
1 ステージあたりの解法は 2〜6 種類(全 65 ステージで約 245 種類)。

## ゲーム性

- **1 ステージ = ハート 3 つで 3 問連続ミッション**。まちがえるとハートが減り、
  0 になるとやり直し(数値は変わる)。クリア時は残りハートがそのまま **★1〜3** になる
- **挑戦モード(単元別チャレンジ)**: クリアした単元には「挑戦 10問」が出現。
  ハート 3 つで 10 問連続 ― **1 問ごとに解法そのものが変わる難度ラダー**
  (例: 平行線と角なら 錯角 → 同側内角 → 折れ線 → ジグザグ → ジグザグの逆算)。
  完走で **👑(王冠)** を獲得。挑戦のスコアも総得点に積み上がる
- **得点 = 100 × 挑戦回数倍率 × ヒント倍率 × スピード倍率 × コンボ倍率**
  - 一発正解 ×2.0 / 2 回目 ×1.4 / 3 回目 ×1.0
  - ヒントを見るたび ×0.7(ヒントは「考え方」→「ほぼ式」の 2 段階)
  - 15 秒以内 ×1.3、30 秒以内 ×1.15
  - コンボは正解のたびに +0.1(最大 ×2.0)。まちがえると 0 に戻る
- **電卓内蔵 ― 紙とペンいらず**: 解答欄には数字だけでなく式が書ける
  (× ÷ + − ( ) √ に対応。例: `12×8÷2`、三平方なら `√(13×13−5×5)`)。
  「＝計算」で途中計算もでき、「こたえる」は式のまま採点される。
  こわれた式はハートを消費せずに教えてくれる
- **わからないときは「解き方」ボタン ― アニメで解説**: 押すたびに解き方が 1 ステップずつ進み、
  補助線がスッと引かれ、注目する部分に色がつき、等しい角に印がつく
  (例: 折れ線問題なら「平行な補助線を引く → 上半分の錯角 → 下半分の錯角 → たす」)。
  時計の針・ブーメラン形・折り返し・葉っぱ形・長方形の中の点・平行線と三角形・
  ヒポクラテスの月などの看板問題は専用のアニメ台本つき。それ以外の問題も
  ヒント→解説を順に見せる汎用ステップで案内する。
  最後の計算は自分で入力して正解する流れ(見た問題は学習扱いで 0 点・コンボはリセット)
- **図に書き込める**: 図を指でなぞると、そのまま手書きで書き込める(黄色の線)。
  計算のメモや「ここが等しい」の印つけに使う。
  図の右上の「補助線」を押している間は**まっすぐな線**になり、端点は
  頂点・辺の中点・円の中心に**スナップ**する(緑の点線)。
  「折れ点を通る平行線」「頂点と中点を結ぶ」など狙った補助線が正確に引ける。
  右上の「もどす」で最後に描いたものを 1 つ消す(手書き・補助線のどちら
  でも)。問題が変わると自動で消える
- **段位**: 総得点で 見習い → 図形たんけん隊 → 角度ハンター → 面積マイスター → 図形の達人 → 図形仙人
- **チャレンジ**: タイムアタック(3 分で何問。コース別/全コースミックス)/
  サバイバル(ミス 3 回まで。正解数が増えるほど難しいステージが出る)。自己ベストが残る
- まちがえたときは正解と解説を表示。リトライは別の数値で出題される

## 特徴

- **問題は全てプロシージャル生成**(`core/gen_*.gd`)。
  余弦定理がきれいに解ける辺の組、ヘロンの公式で面積が整数になる三角形、
  3.14 の計算が小数 2 桁に収まる半径と中心角、などを選んで生成する
- **図形は宣言的スペックから自前レンダラで描画**(`ui/figure_view.gd`)。
  多角形・円・おうぎ形・角の印・直角マーク・等辺チック・方眼と軸・関数のグラフ・
  葉っぱ形・ヒポクラテスの月まで対応。座標系は y 上向きで自動スケーリング
- **縦持ち最適化**: 論理解像度 1080×1920、iPhone のセーフエリア対応、
  日本語フォント(Noto Sans JP)同梱
- **効果音はプログラム生成**(外部アセットなし)

遊ぶ人の学年で 3 つに分かれている。

| モード | 中身 | 遊び方 |
|---|---|---|
| **小学生** | 「たからのちず」1 まいの地図を 23 歩。中学受験レベルの 23 ステージに 1 歩ずつ | ゆびで さわって じぶんで見つける。進むと旗が立ち、先のきりが晴れる。文はぜんぶルビ付き |
| **中学生** | 21 章(小学校の復習 + 中学の内容) | 図を動かして「変わらないもの」を見つける |
| **高校生** | 9 章(高校の内容)。**テーマは別** | 同じ仕組みで、惑星の基地の話に差し替え |

小学生モードは `core/kid_defs.gd`(単元データ)+ `scenes/kid_map.gd`(地図)
+ `scenes/kid_unit.gd`(1 歩の中身)、
高校生モードの文は `core/story_hs.gd`(仕組みは中学生モードのものを借りて、文だけ差し替える)。

## ストーリー(中学生・全21章)

**このアプリの入口**。タイトルの一番上に置いてある。
本編とは**動詞を変えた**モードで、本編が「図が出る → 公式を使って値を答える」なのに対し、
こちらは**公式を知らないところから、図を動かして「変わらないもの」を見つける**。

**通しの筋**: 主人公は測量師トトの見習い。行く先々に「渡りの学者」カラスが
先回りしていて、公式を高く売りつけている。カラスの言うことは**正しいこともあれば
嘘もある**。トトは答えを教えず「測れ」としか言わない。プレイヤーは自分で図を動かし、
カラスの主張が本当かどうかを確かめていく ―― 丸暗記できない、という本編の思想を
そのまま物語の対立にしている。

各章は 5 場面(困っている依頼人とカラスの断言 → 測る → トトが補助線を一本引いて
理由を見せる → **その章の依頼を 1 つ解く** → 依頼が片づき、次の町への引き)。

**依頼に本編の問題をそのまま出さない**(`core/story_tasks.gd`)。
「直線 l と m は平行です。折れ線の角 x は何度ですか」を出すと本編と同じ画面になり、
物語も直前の発見も効かない。「足場が無くて曲がり角には登れない。上下の角だけ測ってきた。
梁は何度で切る?」のように、その章の現場の言葉で書き直す(数値は毎回変わる)。
測る場面は **予想 → 記録 → 判定** の順。選択肢にはカラスの主張が混ざっている。
まず測る前に賭けさせ、
**規定回数を記録するまで答えの選択肢は出ない**(当てずっぽうで進ませない)。
最後に予想が当たっていたかを出す。
中学受験 → 高校受験 → 大学受験の順に並び、前の章をクリアすると次が開く。

| # | 章 | 動かすもの | 見つける決まり |
|---|---|---|---|
| 1 | 三角形の秘密 | 三角形の頂点 | 内角の和は 180° |
| 2 | 壁ぎわの曲がり角 | 折れ線の曲がる場所 | 折れ角 = 上の角 + 下の角 |
| 3 | 五角の広場 | 五角形の頂点 | 内角の和は 540°(何角形でも三角形の数で決まる) |
| 4 | 矢じりの紋章 | へこみの点 | へこんだ角 = ほかの 3 つの角の和 |
| 5 | 斜めに折る | 折り目の角 | 折り返した角 = 180 − 折り目 × 2 |
| 6 | 円のふしぎ | 円の大きさ | 円周 ÷ 直径 = 3.14…(π) |
| 7 | 高さが同じなら | 頂点を横に滑らせる | 底辺と高さが同じなら面積は同じ(等積変形) |
| 8 | 畑を横切る道 | 道の位置 | 道をどこに通しても残る畑は同じ |
| 9 | 水は量で決まる | 水そうの幅 | 幅 × 深さ は水の量そのもの |
| 10 | 影で測る | 太陽の向き | 同じ時刻なら 高さ ÷ 影 はどの物でも同じ |
| 11 | 通せんぼの板 | 板の進んだ長さ | 重なりの面積 ÷ 進んだ長さ は一定(たて) |
| 12 | 直角の宝 | 直角をはさむ 2 辺 | a² + b² = c²(三平方) |
| 13 | 三角定規の秘密 | 三角定規の大きさ | 30° の直角三角形は 斜辺 = 短い辺 × 2 |
| 14 | 円周角のふしぎ | 円周上の席 | 円周角は中心角の半分 |
| 15 | 堀にふれる道 | 対岸の杭 | 接線と弦の角 = 向こう側から見こむ角(接弦定理) |
| 16 | 星形の飾り | 星の頂点 | とがった 5 つの角の和は 180° |
| 17 | 大きくすると | 相似比 | 面積比は相似比の 2 乗 |
| 18 | 倉の梁 | おくゆきと高さ | 対角線² = 3 辺の平方の和(三平方を 2 回) |
| 19 | 二倍の樽 | 拡大の倍率 | 体積比は相似比の 3 乗 |
| 20 | 三角帽子の型紙 | 母線の長さ | ひらいた弧 = 底面の円周(中心角 = 360 × r ÷ l) |
| 21 | 石を切り出す | 底面の角の数 | 頂点 − 辺 + 面 = 2(オイラーの多面体定理) |
| 22 | 池ごしの板 | 渡す向き | 近い方 × 遠い方 は一定(方べきの定理) |

| 26 | 外接円のひみつ | 円周上の頂点 | a ÷ sin A = 2R(正弦定理) |
| 27 | はさむ角と面積 | 2 辺のはさむ角 | 面積 = ½ × a × b × sin C |
| 28 | 巻き上げ機 | 軸の半径 | 弧 ÷ 半径 は角の大きさそのもの(ラジアン) |
| 29 | 羊の囲い | 囲いの上の位置 | (x − a)² + (y − b)² = r²(円の方程式) |

- 章データは `core/story_defs.gd`、図は `core/story_figs.gd`、画面は `scenes/story.gd`、
  章えらびは `scenes/story_select.gd`。挿絵は `scenes/story_art.gd`
- 挿絵は 8 種類(麦の畑・親方の作業場・夕暮れ・劇場・噴水・車輪の工房・
  屋根の骨組み・星空の天文台)。どれも `scenes/story_art.gd` でその場で描いている
- 挿絵も図も**画像ファイルを持たず、その場で図形として描く**ので、どの端末でも
  ぼやけず、アプリの容量も増えない(効果音やアイコンと同じ方針)
- 図の点をつまんで動かす仕組みは `ui/figure_view.gd` の `drag_points` /
  `point_dragged`(本編では使わないので既存の動作に影響しない)
- 角度は**整数に丸めても和が 180 になるように**誤差を分配している。
  ふつうに四捨五入すると 40 + 12 + 129 = 181 と見えて、発見そのものが濁るため
- `tests/story_check.gd` は日本語の文に**キリル文字などが混ざっていないか**も見る
  (書いている途中で紛れこんだことが実際にあり、読める人がいないと気づけないため)
- `tests/story_check.gd` が全章のデータと、**「一定」と言っている量が本当に
  動かしても一定か**(1 章あたり 300 通り)、そして**依頼が毎回ちゃんと
  作れるか**(文・答え・図がそろい、本編と同じ教科書調の語尾で終わっていないか)を
  検証する
- `tests/story_play.tscn` が**中学生モードと高校生モードの全章を通してプレイする**。各場面で
  「つぎへ」が出ることを確かめる ― 依頼(`core/story_tasks.gd`)は本編の問題と
  持っている項目が違うので、無い項目をうっかり読むとそこで関数が止まり、
  ボタンが出ないまま**進めなくなる**(実際に起きた)。データ検証だけでは
  見つからないので、通しプレイを常に回す
- **表には「変わる数」を必ず出す**。定数だけを並べると出来レースに見えて、
  発見の手応えが消える(例: 等積変形の章は辺の長さを、円周角の章は席の位置を出す)

## iOS ビルド(Codemagic)

さわる物理と同じパイプライン。`codemagic.yaml` の `ios-kakudomenseki` ワークフローを
**手動で**回すと、Mac インスタンスで IPA をビルドして TestFlight へ自動アップロードする。
(自動トリガーは付けていない。Mac は分単価が高いので、上げたいときだけ回す)

流れ: 署名ファイル取得 → Godot 4.7.1 + iOS export テンプレート取得 → import ×2 →
`--export-release "iOS"` で Xcode プロジェクト生成(`export_presets.cfg` の iOS プリセット、
`application/export_project_only=true`)→ CFBundleDevelopmentRegion を ja に修正 →
署名して IPA → TestFlight。ビルド番号は Codemagic の `BUILD_NUMBER` で毎回ユニークになる。

事前に Codemagic 側で必要なもの(詳細は `codemagic.yaml` 冒頭のコメント):

1. App Store Connect integration に API キー `historygamekey`(アカウント単位・登録済みを使い回す)
2. 環境変数グループ `appstore_credentials` に `CERTIFICATE_PRIVATE_KEY`(Secret)
3. App Store Connect に Bundle ID `jp.snaplace.kakudomenseki` を登録

App Store の掲載名は次の組み合わせ(タイトル・サブタイトルとも 30 文字まで。
両方が検索対象なので、キーワードはサブタイトルに寄せている):

- タイトル: **図形ハンター**
- サブタイトル: **角度と面積を撃ち落とせ｜中学・高校・大学受験**

App Store Connect に入力する内容(掲載文・キーワード・プライバシー回答・
必要な画像サイズ・未確定事項)は `store/APPSTORE.md` にまとめてある。

## Android ビルド(AAB)

Google Play にあげる AAB は**手元で作る**(Codemagic は iOS だけ。Mac の分単価が高いので)。

```
powershell -ExecutionPolicy Bypass -File tools/build_aab.ps1              # 署名済みリリース版
powershell -ExecutionPolicy Bypass -File tools/build_aab.ps1 -DebugSign   # デバッグ鍵(手元の確認用)
```

書き出したあと `store/check_aab.py` が中身を検める(16KB ページ・targetSdk・
BILLING 権限・versionCode・日本語フォントの同梱)。詳細は `tools/README_BUILD.md`。

初回だけ必要な準備:

1. Godot エディタ設定に Android SDK / JDK のパスを登録
2. Android ビルドテンプレートを導入(`--install-android-build-template` は単独では効かず、
   export と併用する: `godot --headless --path . --install-android-build-template
   --export-debug "Android" build/android/kakudomenseki-debug.aab`)
3. 署名鍵(keystore)を作る → `store/署名鍵の作り方.md`。
   鍵はリポジトリの外(`../keys kakudomenseki/`)に置く

## ストア素材(スクリーンショット)

掲載用の画像は `store/入稿セット/` に**そのままアップロードできる形**で入っている
(Google Play スマホ 1080×1920 / App Store iPhone 6.9インチ 1320×2868・6.5インチ 1284×2778 /
iPad 13インチ 2048×2732 の各 8 枚 + フィーチャーグラフィック 1024×500 + Play 用アイコン 512×512)。
App内課金の審査用スクショ(1242×2208)も同じフォルダに入っている。

作り直す手順:

```
godot --path "<このフォルダ>" res://tests/shot_store.tscn   # 実画面を 1320×2868 で撮る
python store/make_store_images.py                          # 見出しと背景を合成して入稿セットまで作る
python store/check_store_images.py                         # 寸法・枚数・容量・引き伸ばしの検品
```

撮影は App Store の必須枠と同じ最大サイズ(1320×2868)で行い、ほかのサイズは縮小だけで作る
(引き伸ばしを起こさない)。詳細は `store/入稿セット/README.md`。

## アイコン

絵柄は「狙いを定める枠(ハンター)+ 角度の弧と面積の塗り分け(図形)」。
金色は角度と面積だけに使い、枠は淡い青にして主役を邪魔しないようにしている。
小さい表示(ホーム画面の 60px)でも二色の塗り分けと角の弧が残るようにサイズを決めた。

- `icon.svg` … アプリ/エディタ用(角丸つき)
- `store/icon/icon_full.svg` … App Store 用のフルブリード版(角丸・透過なし)
- `store/icon/icon_1024.png` … 上を書き出した 1024×1024(透過なし。iOS 書き出しはこれを参照)
- `store/icon/launcher_192.png` … Android の旧来のランチャーアイコン
- `store/icon/adaptive_fg_432.png` / `adaptive_bg_432.png` … Android のアダプティブアイコン。
  端末ごとに円・角丸などでくり抜かれ、**中央 66%(288px)しか必ず見える保証がない**ため、
  前景は絵柄を 276px に収めて中央に置いている(円マスクでは枠の角は外れ、三角形が残る)
- `store/icon/adaptive_mono_432.png` … Android 13 以降のテーマ付きアイコン用の単色版。
  **指定しないと Godot 既定のロボットのロゴが入る**ので必ず設定する

SVG を直したら PNG を作り直す:

```
godot --headless --path . -s tools/make_icons.gd
```

候補を並べて見くらべたいときは(iOS の角丸を模して 256/120/60 を並べたシートを作る):

```
godot --headless --path . -s tools/icon_preview.gd -- --dir=<svgのフォルダ> --out=<出力png>
```
